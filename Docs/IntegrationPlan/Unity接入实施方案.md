# 将 R11 房间接入原台球游戏：具体实施方案

2026-11-01。范围按用户澄清：第四面墙、球和指定球杆本轮实际完成 Blender 制作；Unity 和游戏规则接入本轮只出方案，不执行替换。

## 最终要得到什么

打开新的 Windows 游戏版本后，玩家进入当前完整房间，使用现有游戏的 8 球/9 球、本地双人/电脑对战、拖动瞄准、后拉松手击球、加塞与结算；击球时看到用户指定的 `magic staff 3d model.glb`，主视角显示靠近母球的前半段。

用户说的“换一个场景”是主要方向。原来的游戏已经有球运动、规则和输入，应该沿用；实际接入还需要让新桌的碰撞/袋口、球杆锚点和游戏相机与新场景对上，再把作者灯光变成适合游戏的烘焙光照。不是重新制作一套台球游戏。

## 一条具体实施路线

### 1. 在原游戏副本建立接入版本

以 `deliverables/Pool3D-Integrated-V1/UnityProject` 的原玩法为底，创建独立候选副本。使用 Unity 2022.3.62f2 / Built-in / Linear，不为这次接入迁移渲染管线或升级 Unity。旧试玩、旧工程和存档保持可回退。

复用已有 `Pool3D-TableReplacement-Prep` 的导出、几何配对和检查方法，但重建资源；该目录旧模型和完整 ZIP 仍为 R3b，不能直接当成最新 R11。完成新资源验证前，不删除待同步保护标记。

**这一步交付：** 独立候选工程与固定的原游戏基线。

### 2. 把场景、球和球杆分别接到现成显示入口

环境导出为 `R11Room` Prefab，绑定 `IntegratedArtAssets.environmentPrefab`。按材质批次导出墙顶/格栅/地毯等静态显示资源，材质节点转成 Unity 可用的贴图与参数。

球继续使用原有 16 个 `ballPrefabs` 和 `IntegratedBallView.Apply(PoolBall[])`。位置、旋转、进袋显隐、8 球模式 16 颗和 9 球模式 10 颗均由原规则/状态决定。Blender 的 `Gameplay preview | Balls - exclude from static room export` 集合只用于制作观察，不合入静态环境，以免开局出现两套球。球不新增 PhysX Rigidbody 来竞争原有模拟。

指定球杆单独导出为 `R11MagicCue` Prefab，绑定 `cuePrefab`。使用真实杆头/杆尾锚点，不按贴图材质名字猜杆头。当前 `IntegratedCueView.Measure` 依赖 `chalked`/`leather_tip`/`rubber` 材质名，新 GLB 是单材质，因此需新增显式 `CueTip`/`CueButt` 读取，并保留旧杆兼容路径。沿用现有 `Apply` 的母球击球点、加塞偏移、后拉量与瞄准角输入；需要的抬杆只影响显示，不借此改写原二维物理。

**这一步交付：** 游戏的旧球状态能显示在新桌上，旧击球输入能驱动新杆。

### 3. 统一桌面、反弹和落袋数据

从最新六段库鼻/袋口轮廓重新导出数据，成套更新：可击球区域、反弹边界、六袋位置/捕获参数、摆球点、自由球合法范围与 AI 几何输入，并生成新的几何 ID/校验指纹。

原因是当前作者模型已经有 R4 连续袋口曲线，而旧候选仍为 R3b 数据。只换显示网格会有看起来撞库/进袋的位置与实际判断不一致的问题。这里更新几何数据与接口，保留原球运动、规则判断、AI 决策和加塞算法。

沿用现有单位接口：模拟为毫米、Unity 游戏显示为厘米、Blender 资产为米。台面 2540×1270 mm、球径 57.15 mm 保持不变，明确轴向与布面/球心高度映射，不能把新房间直接当作 1:1 厘米网格导入。

**这一步交付：** 新桌显示、反弹、袋口、AI 和摆球消费同一套几何。

### 4. 接入玩家击球视角，并处理封闭房间

在现有 CameraSF/OfflineSceneView 上增加或适配击球取景：相机跟随母球和瞄准轴，杆尾大部分位于相机后方，靠近母球的前半段在屏幕下方。保留完整杆体，支持拉杆与抬起观察；不把模型切半来凑镜头。

原拖动瞄准、后拉松手、侧栏力度、击球点和俯视/复位继续保留。球杆拾取使用实际可见投影，避免杆尾在相机后方导致拖动方向错误。对横向加塞、满后拉及各库边位置检查母球和杆头不被裁切、球杆不穿桌边。

四面墙已封闭，展示和游戏相机都必须位于室内。为墙面设置相机专用的简化阻挡/距离限制，防止旋转相机跑到墙外；这些阻挡不参与台球的原二维碰撞。高位俯视相机保持在顶面以下，或明确使用制作/观察专用的顶面显示策略。

**这一步交付：** 玩家在新房间实际操作旧击球流程，看到指定球杆的前半段。

### 5. 烘焙、优化和交付

房间、桌体和家具以静态光照贴图为主，蓝色灯条和暖色灯槽使用发光外观加烘焙照明；反射提前烘焙。球和球杆使用光照探针与少量动态灯，先以一盏主要实时阴影灯为目标。Blender 的多块 Area 灯不直接作为等量 Unity 实时灯搬过去。

袋网使用本轮 R10 的共享简化网格，按实际相机配置远景 LOD；家具、杆架及旧 4K 贴图再按画面占比减面/压缩。球保留原贴图，近景球杆使用 2K 起步，通过实际清晰度判断是否保留更高分辨率。

先完成编辑模式编译、资源引用、几何/锚点/显隐检查与原数值回归，再生成独立 Windows 包供用户试玩。实际 1080p 帧率、GPU/CPU 帧时间、贴图驻留和最差视角需要在运行版测量；不拿 Blender 渲染速度替代。当前不自动启动游戏或跑对局。

**最终交付：** 可回退的新 Unity 工程、独立 Windows 游戏包、检查报告和待用户试玩清单。

## 玩家端验收清单

- 在完整封闭房间里开始原有四种离线模式；8 球/9 球的球数、摆球、回合与结算仍正确。
- 球落在台呢上，撞库/进袋位置对应当前模型；自由球和 AI 目标不指向旧袋口。
- 击球时显示指定球杆的前半段；拉杆、加塞和瞄准方向一致，杆头不离开正确击球点。
- 相机环绕/俯视/复位均不穿出墙壁或被顶面遮死。
- 主要视觉接近作者样板，静态与动态球的明暗衔接自然；性能数字来自实际运行测量。
